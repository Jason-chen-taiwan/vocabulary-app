# Task 6 Report: PWA 殼層

## What Was Implemented

### Module-SW Approach (override applied)
The brief proposed `importScripts('/sw-strategy.js')` in a classic service worker, which breaks because `export` is a syntax error in classic worker scripts. Instead:
- `public/sw-strategy.js` is pure ESM (`export function shouldCache`), importable by both Vitest and the SW.
- `public/sw.js` uses `import { shouldCache } from './sw-strategy.js'` at the top — making it a MODULE worker.
- `components/pwa-register.tsx` registers with `{ type: 'module' }` so the browser loads it as a module worker.

This gives a single source of truth for `shouldCache` with no hacks.

## Icon Generation
Generated with a small Node.js script using only built-ins (`zlib.createDeflateRaw`, `fs.writeFileSync`). The script writes valid PNG binary: signature, IHDR chunk (width/height/RGB), deflate-compressed IDAT with filter-type-0 rows of solid #4f46e5 (indigo) pixels, and IEND. Both files open as valid PNGs at the correct dimensions.

### Fix 2 — session.user.id callback (`auth.ts`)
Added `callbacks.session` inside the lazy return object:
```ts
callbacks: {
  session({ session, user }) {
    if (session.user) session.user.id = user.id
    return session
  },
},
```
**Typing approach:** Parameters left unannotated — TypeScript inferred them from `NextAuthConfig.callbacks.session` (which next-auth v5 types correctly under the database strategy, receiving `{ session: Session, user: AdapterUser }`). No `any` used. Build confirmed TypeScript clean.
